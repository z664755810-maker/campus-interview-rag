## 一、我在这个项目里到底是什么角色

### 1.1 角色定位（一句话）

> **我是这个项目的产品负责人 + 交付实施人：定义需求、评审方案、定位问题、执行部署、验收交付、沉淀文档；代码借助 AI 协作实现。**

这不是自我安慰式的说法，而是一个**在 2026 年完全成立且正在被行业接受的分工模式**。实施顾问、解决方案工程师、数字化交付这类岗位，日常工作本来就是"把标准产品落地到客户现场"——核心能力是需求理解、方案确认、问题定位、部署配置、验收交付、文档输出，写代码反而是次要的。

### 1.2 真实分工表（防追问地图）

这张表是给你自己看的地图：**哪些能讲、哪些要绕**。面试官追问时，你要清楚自己脚下的地面在哪。

| 工作环节 | 我的投入程度 | 具体动作 | 如果被追问，我能撑到什么程度 |
|---|---|---|---|
| 项目选题 | 100% 我决策 | 在考研408 / 技术文档助手 / 面试题库三个方向中拍板选第三个 | 能，理由充分（见 2.1） |
| 需求定义 | 100% 我主导 | 定义 7 大功能模块，决定哪些做、哪些不做 | 能，这是最强项 |
| 方案评审 | 我拍板 | AI 提技术方案，我确认可行性与取舍 | 能讲清"为什么这么设计"，写不出实现 |
| 架构设计 | 我参与确认 | 确认双 Key 设计、同源部署、切分策略 | 能讲数据流，讲不到类与函数的粒度 |
| 代码实现 | AI 主导 | 全部代码由 AI 生成；我提出修改要求、逐段验收 | 讲设计意图可以，讲代码细节会卡 |
| 缺陷发现 | 100% 我主导 | 用截图反馈现象，描述清楚"哪里不对、期望是什么" | 能，这是第二强项 |
| 缺陷定位 | AI 主导，我理解 | AI 从代码中查根因，我判断结论是否合理、是否要采纳 | 能复述结论与逻辑，不能独立读代码定位 |
| 部署上线 | 100% 我执行 | GitHub 推送、Render 建服务、配环境变量、绑卡验证 | 能，独立可复现 |
| 验收测试 | 100% 我执行 | 浏览器全流程实测：载入题库 → 提问 → 看引用 → 刷题 → 模拟面试 | 能，独立可复现 |
| 文档沉淀 | 我发起，AI 起草 | 主动提出要写项目总结与部署剧本，供下个项目复用 | 能，这是我的产品意识体现 |

### 1.3 这个角色对"实施/数字化顾问"为什么是加分项

实施岗招聘方最怕招到两种人：一种是只会背技术名词、到客户现场就懵的；另一种是干了三个月还不敢碰客户环境的。

你的项目恰好证明了三件事：

1. **你敢碰生产环境** —— 从零把系统部署到公网，配环境变量、处理构建失败、绑卡完成验证，全程独自执行；
2. **你能定位问题** —— 不是等别人告诉你哪里错了，而是自己发现异常、描述清楚、推动修复、回归验证；
3. **你有成本意识** —— 全程零成本部署，每一个技术选择都考虑了"免费额度够不够、会不会被限流"，这正是交付岗必须有的资源意识。

### 1.4 与"我独立开发了系统"这句话的距离

诚实评估：如果用"独立开发"来描述，你还差三块：

- **读代码定位问题的能力** —— 目前依赖 AI 查根因，你需要能自己打开文件看逻辑；
- **基础语法与框架的熟练度** —— 能讲设计，不能手写；
- **独立改动代码的能力** —— 目前是"提需求 → AI 改 → 我验收"，目标是"我能自己改，AI 做辅助"。

这三块就是第七节补课清单要解决的目标。**在补上之前，第 8.4 节的追问防线段落是你必须背熟的。**

## 二、我主要负责与参与的工作（5 大块，每块都能讲 3 分钟）

### 2.1 块一：需求定义与产品决策（我 100% 主导）

**我做了什么：**

- **方向决策**：在三个候选方向中选择了「校招面试题库」。理由：① 直接服务我自己的求职场景；② 面试题是天然的结构化 Q&A 语料，一份文档天然就是"一题一问一答"；③ 最能体现 RAG"带出处、防幻觉"的价值；④ 边建库边复习，一举两得。
- **功能取舍**：定义了 7 大功能模块（文档入库 / 语义检索 / RAG 问答 / 引用溯源 / 专题刷题 / 模拟面试 / 题库管理），并明确砍掉了什么（不做用户体系、不做多租户、不做商用）。
- **体验优化决策**：提出三项关键体验改进，其中两项目前已落地：
  - 模拟面试**默认只显示题干，自评后才揭晓答案** —— 理由：如果题干和答案一起渲染，用户一眼就瞟到答案，练习完全失效；
  - 专题刷题**增加难度与题型筛选** —— 理由：不同阶段的人需要练不同难度的题；
  - 内置示例题库**从 50 题扩充到 70 题** —— 理由：首次访问的人不可能自己准备文档，必须开箱就有内容可玩。
- **边界定义**：明确"非商用、学习作品"的定位，据此决定不做的东西（如支付、用户系统），避免范围失控。

**面试怎么讲（示范）：**

> "这个项目的方向和功能是我定的。比如模拟面试这个模块，我要求默认只显示题干——因为如果答案跟题目一起渲染出来，用户眼睛会先瞟到答案，这就失去练习意义了。所以数据建模的时候要把'纯题干'和'题面加答案'分成两个字段，前端默认只拿题干，用户自评完再请求答案。这是从真实使用场景出发的设计，不是技术上怎么方便怎么来的。"

这段话的含金量在于：**它证明了你有产品思维，能从一个使用细节倒推数据建模要求。**

### 2.2 块二：方案评审与技术拍板（我拍板，AI 提建议）

**我做了什么：** 以下技术决策由我确认采纳，其中 2 项直接避免了部署失败：

| 决策 | 结论 | 我的判断依据 |
|---|---|---|
| 后端框架 | FastAPI | 异步、自带接口文档、参数校验是内建的，适合做 API 服务 |
| 向量库 | Chroma（嵌入式） | 学习项目规模小，不需要分布式向量库，嵌入式免运维 |
| Embedding 供应商 | 阿里百炼（默认）+ 智谱（备选） | 智谱免费档会持续限流，必须有不绑定单一供应商的方案 |
| 部署方式 | Docker 多阶段 + 同源托管 | 前端构建产物由后端直接托管，省掉跨域配置，一次部署两个服务 |
| 运行环境 | Python 锁 3.12 | 3.13 装不上 Chroma 的依赖，这是部署构建失败后锁定的 |

**面试怎么讲（示范）：**

> "技术方案是 AI 提的，但每一条我都要求讲清楚'为什么选它、替它的是什么、代价是什么'，确认之后才动手。比如向量库选嵌入式 Chroma 而不是分布式方案，理由是项目数据量在万级以内，嵌入式免运维、成本为零；代价是不能多用户隔离——这一点我明确知道，并且写进了文档的'已知限制'里。"

### 2.3 块三：缺陷发现与功能调优（我 100% 主导）

这是你**最能打的一块**，因为缺陷是你自己发现的，不是别人喂给你的。

**我做了什么：** 累计发现并推动修复 **9 处**功能与文档问题，典型 4 例见第四节（每个都能独立讲 3 分钟）。

**工作闭环是这样的：**

```
用截图发现异常 → 描述清楚"现象是什么、期望是什么" → 确认根因解释合理
→ 确认修复方案 → 修复后回归验证 → 确认线上生效
```

**面试怎么讲（示范）：**

> "我有一套自己的验收习惯：功能上线后我会把每个入口都点一遍，看数据对不对、交互顺不顺。比如我发现专题刷题面板打开是空白的，但换到问答面板再切回来内容就出来了——这种'时好时坏'的问题最容易漏。我把现象描述清楚之后定位到是组件只在首次挂载时加载数据，切面板不会重新触发。修复方案是加上自动加载 + 切换面板时强制刷新。"

### 2.4 块四：部署上线与运维（我 100% 执行）

**我做了什么（完整链路）：**

1. 本地构建前端，确认编译通过；
2. 本地起后端，确认接口能通；
3. 用 GitHub Desktop 提交并推送代码到远程仓库；
4. 在 Render 控制台创建 Web Service，选择 Docker 方式构建；
5. 逐项配置环境变量（模型 Key、向量化供应商、鉴权、限流阈值、向量库路径）；
6. 完成平台账号绑卡与身份验证（Stripe KYC），解锁部署权限；
7. 处理构建失败：定位到运行环境版本不兼容，锁定到 3.12 后构建成功；
8. 线上验收：浏览器实测全流程，确认冷启动、自动灌数据、问答带引用均正常；
9. 明确安全红线：真实密钥只配在平台控制台，绝不写进代码仓库。

**面试怎么讲（示范）：**

> "部署是我一个人从头做到尾的。中间卡了几次，印象最深的是第一次构建失败——Docker 构建日志报依赖安装错误，我发现是构建环境默认用了最新的 Python 版本，而项目依赖里有一个包在那个版本上还没有预编译包。我把运行环境锁到 3.12 之后构建就过了。这件事教会我：**部署失败不要瞎改代码，先看构建日志的错误信息，八成是环境问题。**"

### 2.5 块五：知识资产沉淀与跨项目复用（我发起）

**我做了什么：**

- 主动提出"把项目经验写成文档，给下一个项目复用"，产出 3 份资产：
  - `PROJECT_SUMMARY.md` —— 项目总结（14 节，含架构、接口、数据、限制、时间线）
  - `RENDER_DEPLOY_PLAYBOOK.md` —— 通用部署剧本（可套用到任何同构项目）
  - `CONTRIBUTION_AND_INTERVIEW_GUIDE.md` —— 本手册

## 三、面试前必背的关键内容

### 3.1 项目一句话介绍（30 秒）

> "我做了一个校招面试题库的智能问答系统，已经上线可以访问。用户把面试题文档传上去，系统会自动整理成题库；提问的时候，它能在题库里找到相关题目，生成答案，并且标出答案是从哪几道题来的——这样它就不会瞎编。整个项目从需求、方案、调优到部署上线都是我跟进的，部署在云上，零成本。"

### 3.2 必背数字表（12 个）

数字是面试里最好背、也最能证明"我真做过"的东西。**记住数字后面的"为什么"。**

| 数字 | 含义 | 追问时怎么答 |
|---|---|---|
| **70 道** | 内置示例题库题目数 | "覆盖 10 个学科 70 道题。因为是给首次访问的人开箱用的，所以内置在系统里，服务重启会自动灌回去。" |
| **10 个** | 题库学科数 | "Java、Python、计算机网络、操作系统、数据库、数据结构与算法、设计模式、前端、Redis 与缓存、分布式与微服务。" |
| **4 种** | 题型 | "问答、选择、判断、代码输出。按题型筛选是因为不同题型的练法不一样。" |
| **3 档** | 难度分级 | "基础、进阶、困难。" |
| **14 种** | 支持的文档格式 | "Word、PDF、PPT、Excel、CSV、JSON、HTML、Markdown、TXT 等。因为用户手里的资料格式很杂，不可能只支持 txt。" |
| **12 个** | 后端接口数 | 挑三个讲：上传文档、RAG 问答、按学科列题。 |
| **10MB** | 单文件体积上限 | "免费层内存有限，所以上传时先读字节判断大小，超了直接返回 413，避免大文件把服务打挂。" |
| **30 次/分钟** | 单 IP 限流阈值 | "防止被爬或者被滥用导致额度耗光。单机内存实现，够用。" |
| **1024 维** | 向量维度 | "文本向量化之后每个片段变成 1024 个数字。默认用阿里百炼的模型。" |
| **90 秒** | 模拟面试单题限时 | "模拟真实面试的节奏感。" |
| **3.12** | Python 运行版本 | "必须锁 3.12。最新版本装不上向量库的依赖，这是部署构建失败后排查出来的。" |
| **0 元** | 部署与运行成本 | "Render 免费实例 + 两家大模型的免费额度，全程零成本。每个选型我都算过免费额度够不够。" |

### 3.3 架构一段话（背下来）

系统有两条链路，我用一句话说清：

> **入库链路**：文档上传 → 解析出文字 → 按"题"切成一个个片段 → 每个片段转成向量存进向量库。
> **问答链路**：用户提问 → 把问题也转成向量 → 在库里找出最相近的几个片段 → 把这些片段和问题一起交给大模型 → 大模型基于这些资料生成答案，并标明每一句来自哪个片段。

**关键点（面试官爱问的地方）：**

- 每个片段都带"出身信息"（来自哪个文件、哪个学科、第几题、什么难度）；
- 检索到片段后，会给每段编号，要求大模型**只能用给定资料回答，资料里没有就说没有**；
- 大模型返回后，把编号映射回原始出处，作为引用信息返回前端；
- 前端按结构化数据渲染出处卡片，而不是去解析文本——这样更稳也更安全。

### 3.4 高频问题标准答法（10 问）

> 每题给两个层次：**第一层**是你必须能说的；**第二层兜底话术**是当你被追问到自己不懂的地方时怎么体面地收住，同时不撒谎。

**Q1. 介绍一下这个项目**
→ 用 3.1 的 30 秒版。如果对方是技术面，再补 3.3 的架构一段话。

**Q2. 什么是 RAG？为什么要用 RAG，不直接问大模型？**
→ "RAG 就是'先检索、再生成'。直接用大模型的问题是它可能会编——它不知道的东西也会一本正经地瞎说，而且你不知道它说的是从哪来的。RAG 的做法是先从我们自己的资料库里找出相关内容，再让大模型基于这些内容回答，并且标出出处。这样答案就有据可查，也能避免瞎编。"
→ *兜底*："更底层的向量检索算法细节我还在补，但我能说清它解决的问题和整体流程。"

**Q3. 为什么按"题"切分，而不是按字数切分？**
→ "因为这是面试题文档，一道题本身就是一个完整的语义单元。如果按固定字数切，一道题的题干和答案可能被切到两个片段里，检索出来只有半道题，大模型就没法回答。按题切能保证每段的语义是完整的。"
→ 这里可以补一句加分："当然这种方式依赖文档格式规整，所以我另外做了一套兜底逻辑：遇到不是标准题目格式的文档，会自动降级成通用切分，并打上'通用文档'标记，模拟面试时默认排除这类内容。"

**Q4. 怎么防止大模型胡说（幻觉）？**
→ "三道防线：第一，提示词里明确要求只能使用给定资料，资料里没有就说不知道，不许自己发挥；第二，答案必须带出处，每个片段有编号，用户能点开看到原文核对；第三，检索时设了相似度阈值，太不相关的片段直接过滤掉，不给大模型当素材。"

**Q5. 什么是 embedding？为什么要向量化？**
→ "embedding 就是把一段文字变成一串数字，也就是一个坐标。语义相近的文字，它们的坐标就靠得近。这样我们就能用数学方法算'哪两段话意思最像'。如果不做向量化，就只能做关键词匹配——用户问'三次握手'，文档里写的是'TCP 建连过程'，关键词对不上就搜不出来，但向量能算出来它们意思接近。"

**Q6. 向量库用的什么？为什么选它？**
→ "用的是 Chroma，嵌入式的方式跑。选它是因为项目数据量不大，嵌入式不需要单独部署服务、零运维、零成本。代价是不能做多用户隔离，也不能横向扩展——这一点我清楚，也写在文档的限制章节里了。"

**Q7. 项目里遇到最大的困难是什么？**
→ 讲第四节的"部署失败：运行环境版本不兼容"或"页面空白"故事。**挑一个你从头参与、有细节的讲，不要挑最难的。**

**Q8. 你怎么保证系统稳定和安全？**
→ "有几层：接口都有密钥校验，没有效的密钥访问不了；按 IP 限流，一分钟超过 30 次就拒绝；上传文件限制大小和格式；数据库如果被清空，服务启动时会自动把内置题库灌回去，不会出现'打开是空的'；真实密钥全部配在云平台的环境变量里，不写进代码仓库。"
→ 这是**加分题**，因为大部分人做学习项目根本不会考虑这些。

**Q9. 为什么要做鉴权和限流？**
→ "鉴权是防止别人随便调接口；限流是防止额度被耗光——我用的都是免费额度，如果被刷一下就用完了，服务就废了。而且顺序有讲究：先验密钥再限流，这样无效请求不会占用限流配额。"

**Q10. 这个项目有什么不足？下一步怎么优化？**
→ 诚实列出（**这一题答得好非常加分，说明你有清醒认知**）：
> "三个明确的不足：第一，向量库是嵌入式的单机方案，没做多用户知识库隔离；第二，限流是基于单机内存的，多实例部署就不准了，要换成 Redis；第三，检索目前只用向量，可以再加关键词检索做混合召回，再上一层重排模型，效果会更好。"

### 3.5 五个必须记住的技术名词

| 名词 | 一句话解释（对 HR 也能说） |
|---|---|
| RAG（检索增强生成） | 先在自己的资料库里找相关内容，再让大模型基于这些内容回答，答案带出处 |
| Embedding（向量化） | 把文字变成一串数字坐标，语义相近的文字坐标就接近 |
| 向量检索 | 用数学方法计算哪两段文字意思最接近 |
| 引用溯源 | 答案里标明每句话是从哪段资料来的，用户可点击核对 |
| 中间件 | 请求进入系统前先经过的"关卡"，比如先验身份、再查频率 |

## 四、调优依据：4 个能讲的故事

> **为什么这一节重要**：面试官问"你做了什么"时，故事比清单有说服力。这 4 个都是你真实发现的问题，每个都能套用同一个结构讲：**现象 → 我的判断 → 怎么定位 → 怎么修 → 学到什么。**

### 故事 1：专题刷题面板打开是空白的

- **现象**：切到"专题刷题"面板，列表是空的；但如果先切到别的面板再切回来，内容就出现了。
- **我的判断**：数据本身没问题（切回来能看到），所以不是数据的问题，是"加载时机"的问题。
- **定位结果**：这个组件只在页面第一次加载时请求一次数据；而且切换面板用的是"隐藏/显示"而不是"销毁重建"，所以组件一直活着，不会再触发第二次加载。
- **修复**：改成组件初始化时自动加载，并且在切换到该面板时主动触发一次刷新。
- **学到什么**：**前端组件有"生命周期"这个概念**——组件被创建、被更新、被销毁的时机不同，行为就不同。"隐藏"不等于"销毁"，这是一个很容易踩的坑。
- **一句话总结（面试用）**："这种时好时坏的问题最容易被漏掉。我的经验是：先判断是数据问题还是时机问题，判断依据就是'换个操作路径能不能复现'。"

### 故事 2：左上角写着"示例题库 50 道"，实际有 70 道

- **现象**：上传面板左上角显示"50 道"，但我们实际内置了 70 道题。
- **我的判断**：这是个写死的数字，没有跟着实际数据走。
- **修复**：改成读后台返回的真实数量来显示，并留了一个默认值兜底。
- **学到什么**：**任何展示给用户的数据都不能硬编码。** 这是很典型的"开发时省事、上线后打脸"的问题。
- **加分延伸**："这个数字出现不一致，说明我当时扩充题库到 70 道的时候，有几处旧描述没跟着改。所以后面我做了一次全局体检，把项目里所有提到题数的地方全部统一核对了一遍——包括文档里的。"

### 故事 3：模拟面试里答案和题目一起显示出来

- **现象**：进入模拟面试，题干下面直接跟着答案，练习失去意义。
- **我的判断**：题目和答案在数据里是混在一起的，前端拿到什么就渲染什么。
- **修复**：数据建模时把"纯题干"和"题面+答案"拆成两部分；默认只把题干发给前端，用户自评完再给完整内容。
- **学到什么**：**数据结构要跟着业务场景设计，不是怎么方便怎么存。**
- **一句话总结（面试用）**："这个问题的本质不是前端显示的问题，是数据建模没考虑使用场景。如果只在前端用样式藏起来，懂点技术的人一看源码就拿到答案了。"

### 故事 4：向量化接口一直报 429，整个入库流程走不通

- **现象**：上传文档时一直失败，错误码 429。
- **我的判断**：429 是"请求太多"的意思，说明用的这家模型服务在限流。
- **定位结果**：这家供应商的免费额度是**账户级**限流，不是并发级的——也就是说不只是当下请求多，而是这个账号整体被限制了，换个时间也一样。
- **修复**：在向量化这一层加了一个"供应商切换开关"，通过环境变量就能换到另一家模型服务，代码不用改。切换后问题解决。
- **学到什么**：**外部依赖不能只绑一家。** 免费服务一定会有各种限制，方案里要预留降级路径。
- **一句话总结（面试用）**："这件事让我理解了一件事：依赖第三方服务的时候，一定要问清楚它的限制是什么——是并发限制还是账号级限制，这决定了你有没有办法绕开。如果只绑一家，它一挂你就没招了。"

## 五、部署流程要点

### 5.1 部署链路（一张图记）

```
代码推到 GitHub
      ↓
云平台自动拉取，用 Docker 构建
      ├─ 第一步：构建前端 → 产出静态文件
      └─ 第二步：装后端依赖 + 把前端的静态文件塞进后端
      ↓
启动服务 → 自动检查题库是否为空 → 空就自动灌入内置题库
      ↓
用户访问网址 → 根路径是前端界面，/api 走后端（同一个域名，不用配跨域）
```

### 5.2 操作五步（能背下来）

1. **本地验证**：先构建前端确认编译通过，再本地起后端确认接口能通。
2. **提交推送**：用 GitHub Desktop 提交并推到远程仓库。
3. **创建服务**：在云平台新建 Web Service，选择 Docker 方式，绑定仓库和分支。
4. **配置环境变量**：模型 Key、向量化供应商选择、鉴权密钥、限流阈值、向量库路径。
5. **线上验收**：等构建完成，浏览器实测全流程——载入题库 → 提问 → 查引用 → 刷题 → 模拟面试。

### 5.3 三个致命坑（都是真踩过的）

| 坑 | 现象 | 原因 | 解法 |
|---|---|---|---|
| 运行环境版本太新 | Docker 构建时依赖安装失败 | 项目依赖里有个包在新版本上还没有预编译包 | 把运行环境锁到 3.12 |
| 用命令行方式读端口 | 服务起不来 | 不同平台的命令行展开方式不一样，会解析失败 | 改成用代码直接读环境变量 |
| 自动灌数据阻塞了启动 | 服务反复重启，一直起不来 | 灌数据耗时太长，超过平台的健康检查时间，被判为"启动失败"就重启，陷入死循环 | 改成后台线程执行，不阻塞主流程 |

### 5.4 验收清单（每次上线都走一遍）

- [ ] 打开网址能正常加载页面（首次冷启动慢是正常的，免费实例会休眠）
- [ ] 题库里有数据（说明自动灌入生效了）
- [ ] 上传一份文档能成功入库
- [ ] 提问能返回答案，且答案下面有引用出处
- [ ] 专题刷题能看到题目列表，筛选条件生效
- [ ] 模拟面试只显示题干，自评后才出答案

### 6.1 最能打动招聘方的 6 个亮点（讲业务价值，不讲技术名词）

## 八、怎么向 HR 表述（照抄即可）

### 8.1 30 秒版（HR 初面，对方不懂技术）

> "我做一个校招面试题库的智能问答系统，已经上线了，浏览器打开就能用。用户把面试题资料传上去，系统自动整理成题库；提问的时候，它能在题库里找到相关题目，生成答案，并且标出这道题是从哪来的——这样就不会瞎编答案。整个项目从需求、方案、调优到部署上线都是我负责跟进的，部署在云上，零成本。"

**要点**：不提技术名词，只说"有什么用、谁在用、你在里面干了什么"。

### 8.2 2 分钟版（技术面 / 用人经理）

> **背景**：我在准备校招，需要大量刷面试题，但网上的资料很分散，搜索又搜不准，所以想做一套自己的题库系统。
>
> **我做了什么**：方向是我定的，选的是面试题库这个方向，因为面试题本身就是"一问一答"的结构，最适合做这个。功能我定了七块：文档入库、语义检索、智能问答、引用溯源、专题刷题、模拟面试、题库管理。我特别要求模拟面试默认只显示题干，因为答案和题目一起显示的话，练习就没意义了——这就要求数据模型把题干和答案拆开存。
>
> **技术方案**是我确认后采纳的：后端用 Python 的 FastAPI，向量库用嵌入式的 Chroma，大模型接了两家供应商做备份。
>
> **过程中解决的问题**：印象最深的有两个。一个是部署时构建一直失败，我从构建日志里发现是运行环境版本太新，有个依赖包还没适配，锁到 3.12 就好了。另一个是页面打开空白——现象是切走再切回来内容就出来了，所以我判断不是数据问题而是加载时机问题，最后定位到组件只在首次加载时取数据。
>
> **结果**：系统已经上线，内置 70 道题覆盖 10 个学科，支持 14 种文档格式，整个部署零成本。我也把部署流程写成了文档，下一个项目可以直接复用。
>
> **我的短板**：代码实现这块我是借助 AI 工具协作完成的，我能讲清系统的设计逻辑和每一处为什么这么设计，但具体的代码语法细节我还在补。我目前投的岗位更看重把方案落地、把系统跑起来的能力，这部分是我实际做的。

**要点**：主动承认短板并立刻接到岗位匹配上。**坦诚 + 有落点**，比含糊其辞安全得多。

### 8.3 简历怎么写

见第 6.3 节的三条 bullet 和 6.4 的一句话描述，直接复制。

**三条原则：**
1. **动词用"主导、负责、独立完成、配置、验证"，不用"编写、开发"** —— 这是你真实做的，也避免了被追问代码细节；
2. **数字必须有** —— 70 题、10 学科、14 格式、12 接口、9 处问题、0 成本；
3. **"调优"要写出依据** —— 不要写"优化了性能"，写"定位并修复了前端加载时机、数据一致性等 9 处问题"，有具体类型才可信。

### 8.4 【最关键】被追问代码时怎么答

这是整份手册最重要的一页。**分三种追问强度，对应三档答法。**

**第一档 · 轻度追问："这个项目是你自己做的吗？"**

> "是，从方向、功能、方案到部署上线都是我跟进的。"

这是真的，不用心虚。

**第二档 · 中度追问："代码是你自己写的吗？"**

> "代码是我借助 AI 工具实现、并且逐段验收的，我负责方案设计、问题定位和部署交付。系统每一层为什么这么设计、每个问题怎么排查的，我都能讲清楚；具体的代码语法细节我还在补，这也是我目前重点在提升的地方。"

**原则：不否认、不硬撑、立刻把话题引向你真实做过且能讲透的部分（部署、调优、需求）。**

**第三档 · 重度追问："那你现场说说这个功能是怎么实现的？"**

按你的实际掌握分档处理：

- **能讲的**（架构、数据流、为什么要这么做、怎么排查的问题）→ 大方讲，这是你的主场；
- **只知道作用、不知道实现的** → 这样说：
  > "这一层的具体实现是 AI 协作完成的，我理解它的作用是[X]，也知道为什么要这么做。更细的代码级实现在补，不想给您讲我没吃透的东西。"
- **完全不懂的** → 这样说：
  > "这块我确实还没掌握，我们项目里这一步的作用是[X]，但具体怎么实现的我说不清楚。"
  > **然后立刻补一句**："不过部署这块我是全程自己做的，比如构建失败那次我是从日志里定位到运行环境版本问题的——这类工程问题可能是我更擅长的地方。"

**⚠️ 三条铁律：**
1. **绝对不要编。** 面试官问三句就能知道你是背的还是真懂的，编造被拆穿比承认短板严重十倍；
2. **不要反复道歉。** 一句"这块还在补"就够，然后立刻转到你能讲的；
3. **永远准备一个"我真实解决的工程问题"**作为话题切换的落点。你的最佳选择是**部署构建失败排查**（见 5.3）或**页面空白问题排查**（见第四节故事 1）——这两个你从头到尾参与，细节最牢。

### 8.5 不同岗位的侧重调整

| 岗位方向 | 重点讲什么 | 弱化什么 | 必须补的 |
|---|---|---|---|
| **实施工程师 / 数字化顾问**（你的主方向） | 需求理解与功能边界定义、部署全流程、问题定位闭环、文档沉淀与复用、成本意识 | 算法与代码细节 | P0 + 需求/部署话术 |
| **后端开发（Python 初级）** | 接口设计、参数校验、鉴权限流分层、异常兜底 | 不要主动讲产品功能 | P0 全部 + P1 的 3、4、5 项 |
| **AI 应用 / 解决方案** | RAG 概念与防幻觉机制、双供应商降级、引用溯源的价值 | 前端细节 | P0 的 1、2 项要讲得比标准答案更深 |

### 8.6 可以反问 HR 的问题（显得专业）

1. "这个岗位入职后，典型的一天大概是什么节奏？是常驻客户现场还是以远程支持为主？"
2. "新人一般多久能独立负责一个模块或一个客户？中间的培养方式是老带新还是有系统的培训？"
3. "团队现在交付的产品是标准化的还是定制化的？如果是定制为主，需求变更是怎么管理的？"
4. "您觉得在这个岗位上，做得比较好的同事通常具备什么特质？"（这个问题特别好，能让你知道对方看重什么）

## 九、红线清单（面试前最后看一眼）

| 🚫 不要说 | ✅ 改成 |
|---|---|
| "我独立开发了这个系统" | "我主导了这个项目从需求到部署的全过程" |
| "我用 FastAPI 写了 12 个接口" | "系统有 12 个接口，我参与了接口设计和验收" |
| "我精通 Python / Vue3" | "我熟悉 Python 后端的开发流程，能读懂和调试项目代码" |
| "我做了 RAG 算法优化" | "我在 RAG 链路上做了供应商降级和检索参数调整" |
| "性能优化了 30%"（拿不出数据的话） | "我定位并修复了 X 处问题，每处都做了回归验证" |
| "这个系统能支持高并发" | "限流是单机内存实现，多实例部署要换 Redis，这是我们已知的优化点" |
| 被问代码时："是我一个字一个字敲的" | "代码是我借助 AI 工具实现并逐段验收的，我负责方案、调优和部署" |
| 被问不懂的东西时：硬编一个答案 | "这块我还没吃透，不想讲我没掌握的东西，我可以说说它在我们系统里解决什么问题" |
