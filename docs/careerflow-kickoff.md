## 一、目标与完成标准（待对齐）

### 1.1 一句话定位
**为郑鑫源（27 届计算机本科，求职方向：实施工程师/数字化实施顾问）打造的「简历 + JD 匹配 + 申请追踪 + 面试准备」一体化助手。**

### 1.2 完成标准（候选清单，待用户勾选）
- [ ] **简历管理**：上传 PDF/DOCX → 自动解析为结构化 JSON（基本信息、教育、项目、技能、证书）
- [ ] **JD 解析**：粘贴文本或上传 PDF → 提取岗位要求（技能、工作年限、行业、薪资）
- [ ] **匹配度评分**：简历 ↔ JD 用向量匹配 + 关键词重合，给出 0~100 分 + 高亮差距
- [ ] **简历优化建议**：LLM 基于 JD 生成"针对该 JD 的简历改写"建议（针对实施工程师方向）
- [ ] **申请追踪**：手填或导入公司/岗位/状态/投递日期/HR 联系方式，可按状态筛选
- [ ] **面试准备**：JD + 公司 → 自动生成"该公司高频面试题"（可与 RAG 项目联动）
- [ ] **薪资对比**：同行业同岗位薪资区间（中位数 + P25/P75）
- [ ] **Offer 对比**：多 Offer 并列展示（薪资/福利/成长性）

### 1.3 非功能性要求
- 多端访问（Web 为主，**手机响应式**是必须）
- 数据本地持久化（SQLite）
- 鉴权 + 限流（沿用作品集 #2 的 API Key 中间件）
- 部署 Render Free（沿用作品集 #2 的多阶段 Dockerfile + Environment）

## 二、技术栈（建议沿用 + 少量新增）

| 层 | 选型 | 来源 | 备注 |
|---|---|---|---|
| 后端 | **FastAPI + Pydantic** | 沿用 #2 | 同样的鉴权 + 限流模式 |
| 数据库 | **SQLite**（本地 + Render 磁盘挂载） | 新增 | 比 Chroma 更适合结构化数据 |
| 简历解析 | **pdfplumber**（PDF） + **python-docx**（DOCX） | 新增 | 不上 OCR（图片版 PDF 复杂） |
| JD 匹配 | **DashScope embedding + 余弦相似度** | 沿用 #2 | 与 #2 同一套密钥 |
| LLM | 智谱 **GLM-4-flash** | 沿用 #2 | 便宜不限流 |
| 前端 | **Vue3 + Vite + TailwindCSS** | 沿用 #2 | 加 Tailwind 写响应式更快 |
| 部署 | **Render Free** | 沿用 #2 | 同款多阶段 Dockerfile |

**不引入的复杂依赖**：
- ❌ Next.js（前端太重）
- ❌ PostgreSQL（SQLite 够用）
- ❌ OCR（Tesseract/PaddleOCR）（作品集不需要）
- ❌ 实时通知（WebSocket/SSE）—— 求职追踪不是实时系统

## 三、核心概念（讲师带练时讲清）

1. **简历解析 = 半结构化抽取**：正则 + 启发式 + LLM 兜底
2. **JD 匹配 = 多维度相似度**：向量（语义）+ 关键词（精确）+ 标签（共现）
3. **申请追踪 = CRUD 表格**：状态机 5 态（投递 → 笔试 → 一面 → 二面 → Offer/拒）
4. **面试准备 = 与作品集 #2 联动**：调用 #2 的 RAG 接口，按"该公司+岗位"检索高频题

## 四、最小可跑架构（v0.1）

```
[Vue3 + Tailwind 前端]
  ├─ 简历上传 + 解析结果展示
  ├─ JD 粘贴 + 匹配度评分
  ├─ 申请追踪表格
  └─ 面试准备（调 #2 RAG API）
       ↓ REST + X-API-Key
[FastAPI 后端]
  ├─ /resume/upload (POST, file)  → pdfplumber/python-docx 解析 → JSON
  ├─ /jd/match (POST, body)        → embedding + 余弦 → score + 高亮
  ├─ /applications (CRUD)          → SQLite
  └─ /interview/prep (POST)        → 转发到 #2 的 /api/ask
       ↓
[SQLite（resumes, applications, jds, scores）]
[作品集 #2 RAG 服务]（跨服务调用，X-API-Key）
[阿里 DashScope + 智谱 GLM]
```

## 五、分阶段实施（每步可跑可验证）

| 阶段 | 目标 | 关键交付物 | 验证方式 |
|---|---|---|---|
| **0** | 脚手架 | FastAPI 空服务 + Vue3 空页面 + Tailwind | 同源部署到 Render，浏览器访问 200 |
| **1** | 简历解析 | `/resume/upload` 接 PDF/DOCX，返回字段完整 | 上传 1 份真实简历，能解析出姓名/学校/项目 |
| **2** | JD 解析 + 匹配 | `/jd/match` 输入 JD 文本 + 简历 ID，返回分数 | 用真实 JD 跑出分数，看高亮是否合理 |
| **3** | 申请追踪 | SQLite 表格 + Vue 列表 + 状态筛选 | 增删改查 5 条记录，刷新不丢 |
| **4** | 面试准备联动 #2 | `/interview/prep` 调 #2 /api/ask | 输入"字节跳动 实施工程师"，返回带引用的高频题 |
| **5** | 部署上线 | Render + 环境变量 + auto-seed 简历模板 | 浏览器访问，能完整跑通"上传→匹配→追踪→面试" |

## 八、踩坑预警（作品集 #2 已踩，#3 别再踩）

| 坑 | 体现 | 规避方式 |
|---|---|---|
| API Key 裸贴 | 配额被打爆 | 只走 Render Environment |
| 沙箱 git push 走不通 | Could not connect to server | GitHub Desktop 推送 |
| Free 实例冷启动 | 首次访问 30-60 秒 | 前端加 loading + UptimeRobot 心跳 |
| Chroma 坐标不同源 | 检索翻车 | 入库 + 查询走同一个 embedding |
| **PDF 解析乱码** | pdfplumber 读图片型 PDF 拿到 0 字节 | **用 pdfplumber.extract_text()，且页面 text 为空时 fallback 提示"图片版 PDF 请先 OCR"** |
| **SQLite 文件丢失** | Render Free 重部署清空 | 磁盘挂载 + 启动时检测空库 auto-seed 演示简历 |
