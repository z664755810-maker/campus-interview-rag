## Java

### Q1. [基础] HashMap 的底层原理是什么？
HashMap 基于「数组 + 链表/红黑树」。key 的 hashCode 经过扰动函数后与数组长度取模得到桶下标；发生哈希冲突时用拉链法存储。链表长度超过 8 且数组容量 ≥ 64 时转为红黑树，查询从 O(n) 退化保护为 O(log n)。JDK 1.8 之后头插法改为尾插法，避免并发扩容时形成环。

### Q2. [进阶] ConcurrentHashMap 如何保证线程安全？
JDK 1.8 的 ConcurrentHashMap 摒弃了分段锁，改用「CAS + synchronized 细粒度锁」：读操作基本无锁；写操作只锁当前桶的头节点，不同桶之间互不阻塞，并发度更高。size() 等统计用 baseCount + CounterCell 分段累加，避免为计数加全局锁。

### Q3. [JVM] 说一下 JVM 内存结构与垃圾回收。
JVM 运行时数据区分为线程私有（程序计数器、虚拟机栈、本地方法栈）与线程共享（堆、方法区/元空间）。垃圾回收主要工作在堆上，通过可达性分析（GC Roots 出发）判定对象是否存活；常见回收算法有标记-清除、复制、标记-整理，主流收集器如 G1 把堆划分为 Region 做增量回收，平衡吞吐与停顿。

### Q4. [并发] synchronized 和 ReentrantLock 的区别？
synchronized 是 JVM 内置关键字，自动加解锁，支持锁升级（偏向锁→轻量级锁→重量级锁）；ReentrantLock 是 API 层面的锁，需手动 unlock，支持可中断、公平锁、多条件变量 Condition，在需要细粒度控制或超时获取锁时更灵活。

### Q5. [基础] 面向对象的三大特性是什么？
封装（隐藏内部实现、暴露接口）、继承（子类复用父类能力、建立 is-a 关系）、多态（同一接口不同实现，运行期根据实际类型分派方法）。多态是面向对象最核心价值，让程序对扩展开放、对修改封闭。

## Python

### Q1. [基础] list 和 tuple 的区别？
list 可变（可增删改），tuple 不可变（创建后不能修改）。因此 tuple 可作为字典 key、性能略好、语义上表示固定结构。函数返回多个值本质就是返回一个 tuple。

### Q2. [进阶] GIL 是什么？对多线程有什么影响？
GIL（全局解释器锁）保证同一时刻只有一个线程执行 Python 字节码。因此 CPU 密集型多线程无法利用多核，需用多进程（multiprocessing）绕过；IO 密集型因等待时会释放 GIL，多线程仍有收益。

### Q3. [基础] 浅拷贝和深拷贝的区别？
浅拷贝只复制对象本身，内部引用的子对象仍指向原对象（copy.copy）；深拷贝递归复制所有层级，完全独立（copy.deepcopy）。修改浅拷贝里的可变子元素会影响原对象，深拷贝则不会。

### Q4. [进阶] 什么是装饰器（decorator）？
装饰器是接收函数、返回新函数的高阶函数，用于在不修改原函数代码的前提下增强其行为（如日志、鉴权、计时）。语法糖 `@decorator` 本质是 `f = decorator(f)`。带参数的装饰器是三层嵌套函数。

### Q5. [进阶] 迭代器和生成器有什么区别？
迭代器是实现了 `__iter__/__next__` 的对象，按需取数；生成器是用 `yield` 的函数，调用时返回生成器对象，每次 `next` 执行到 yield 暂停并保留状态。生成器更省内存，适合处理海量或无限序列。

## 计算机网络

### Q1. [基础] TCP 三次握手的过程？
客户端发 SYN；服务端回 SYN+ACK；客户端再发 ACK。三次握手确保双方收发能力正常，并同步初始序列号，防止历史连接干扰。

### Q2. [基础] TCP 和 UDP 的区别？
TCP 面向连接、可靠、有序、流量/拥塞控制，适合文件/网页等要求完整的场景；UDP 无连接、不可靠但低延迟，适合音视频、游戏、DNS 等对实时性敏感的场景。

### Q3. [基础] HTTP 和 HTTPS 的区别？
HTTPS = HTTP + TLS/SSL 加密。HTTP 明文传输，易被窃听篡改；HTTPS 通过非对称加密协商密钥、对称加密传输数据，并借助证书验证服务端身份，防止中间人攻击。默认端口分别为 80 与 443。

### Q4. [进阶] 浏览器输入 URL 到页面展示经历了什么？
DNS 解析域名→TCP 三次握手建立连接→发送 HTTP 请求→服务器响应 HTML→浏览器解析 DOM/CSSOM 构建渲染树→布局与绘制；期间可能触发重定向、CDN、缓存命中，JS 还会阻塞或异步加载。

### Q5. [基础] 301、302、304 状态码的区别？
301 永久重定向（资源已迁移，浏览器会缓存）；302 临时重定向（每次重新请求）；304 Not Modified 表示资源未变，客户端直接用本地缓存，不重新下载，属协商缓存成功。

## 操作系统

### Q1. [基础] 进程和线程的区别？
进程是资源分配的最小单位，拥有独立地址空间；线程是 CPU 调度的最小单位，同一进程内线程共享内存。线程切换开销小于进程，但一个线程崩溃可能影响整个进程。

### Q2. [基础] 虚拟内存的作用？
虚拟内存为每个进程提供独立的连续地址空间，通过页表映射到物理内存，配合缺页中断实现按需加载，既能让你运行比物理内存更大的程序，也实现了内存隔离与安全。

### Q3. [进阶] 死锁的四个必要条件与避免方法？
四个条件：互斥、持有并等待、不可剥夺、循环等待。避免思路：破坏任一条件，如按固定顺序获取锁（破坏循环等待）、一次性申请全部资源、设置锁超时与回退。银行家算法可在分配前预判是否进入不安全状态。

### Q4. [基础] 常见的进程调度算法？
先来先服务（FCFS）、短作业优先（SJF）、时间片轮转（RR，交互友好）、多级反馈队列（按优先级+时间片，兼顾吞吐与响应）。调度目标通常是高吞吐、低延迟、公平。

### Q5. [进阶] 分页和分段的区别？
分页是物理概念，把内存按固定大小页划分，用户无感，主要解决碎片与外存交换；分段是逻辑概念，按程序结构（代码段、数据段）划分，用户可见，便于保护与共享。段页式结合二者优点。

## 数据库（MySQL）

### Q1. [基础] 什么是索引？为什么 B+ 树适合做索引？
索引是有序数据结构，让查询不必全表扫描。B+ 树高度低（多路平衡）、叶子节点用链表串联，范围查询和排序极快，且非叶子节点只存键不存数据，单页能放更多键、降低 IO 次数。

### Q2. [基础] 事务的 ACID 与隔离级别？
原子性（全部成功或全部回滚）、一致性（满足约束）、隔离性（并发互不干扰）、持久性（提交后落盘）。隔离级别：读未提交→读已提交→可重复读（MySQL 默认）→串行化，级别越高越安全但并发越差，需在一致性与性能间权衡。

### Q3. [进阶] 一条慢 SQL 怎么优化？
先用 EXPLAIN 看执行计划，确认是否走索引；避免 `SELECT *`、函数包裹索引列、隐式类型转换导致索引失效；大表加合适索引、分页用游标而非 LIMIT 大 offset；必要时拆表或冗余预聚合。

### Q4. [基础] 内连接、左连接、右连接的区别？
内连接只返回两表匹配的行；左连接返回左表全部 + 右表匹配（无匹配补 NULL）；右连接反之。统计「存在/不存在」关系时左连接 + IS NULL 很常用。

### Q5. [基础] 数据库三大范式？
第一范式（字段原子不可再分）、第二范式（消除部分依赖，非主属性完全依赖主键）、第三范式（消除传递依赖）。实际常适度反范式以换查询性能。

## 数据结构与算法

### Q1. [基础] 数组和链表的区别？
数组连续存储、随机访问 O(1)、插入删除 O(n)；链表节点离散、插入删除 O(1) 但访问需遍历 O(n)。数组缓存友好，链表动态扩容灵活。

### Q2. [基础] 快速排序的思想与复杂度？
分治：选基准 pivot，将数组按大小分到两侧，递归处理子区间。平均 O(n log n)，最坏（已排序且选端点在 pivot）O(n²)。工程上常随机选 pivot 或三数取中，并对小子区间用插入排序。

### Q3. [基础] 二叉树的四种遍历？
前序（根左右）、中序（左根右，二叉搜索树中序即有序）、后序（左右根）、层序（BFS 按层）。递归与栈/队列可相互改写，后序非递归需标记访问状态。

### Q4. [基础] 哈希表怎么解决冲突？
开放定址法（线性/二次探测、再哈希）与链地址法（拉链）。拉链法实现简单、删除方便，负载因子过高时扩容并重哈希；Java HashMap 在链表过长时转红黑树。

### Q5. [进阶] 堆（优先队列）是什么？
堆是满足「父节点 key 不小于/不大于子节点」的完全二叉树，用数组存储。大顶堆根最大，小顶堆根最小。插入/取顶都是 O(log n)，Top-K、定时器、堆排序都依赖它。

## 设计模式

### Q1. [基础] 单例模式怎么实现？有什么坑？
保证类只有一个实例并提供全局访问点。饿汉式（类加载即建，线程安全但可能浪费）、懒汉式（双重检查锁 DCL + volatile 防指令重排）。坑：反射/反序列化可破坏单例，分布式下需配合外部存储。

### Q2. [基础] 工厂模式解决什么问题？
把对象的创建与使用解耦：简单工厂集中判断、工厂方法让子类决定创建、抽象工厂生产产品族。优点是符合开闭原则，新增产品不改已有调用方，只加工厂实现。

### Q3. [进阶] 观察者模式的应用场景？
定义一对多依赖，主题状态变化时自动通知所有观察者。典型场景：事件总线、消息订阅、UI 与Model 绑定（如 Vue 响应式）。注意避免循环通知与内存泄漏（及时注销观察者）。

### Q4. [进阶] 策略模式怎么用？
把可互换的算法封装成独立策略类，上下文持有一个策略接口，运行时注入不同实现。相比一堆 if/else，新增策略不修改上下文，符合开闭原则。常用于促销、排序、校验规则。

### Q5. [基础] 什么是 MVC？
Model（数据与业务）、View（展示）、Controller（接收输入、协调二者）。请求经 Controller 改 Model，Model 变化通知 View 刷新。分层让前后端职责清晰、便于测试与协作。

## 前端（HTML/CSS/JS）

### Q1. [基础] 什么是闭包（closure）？
函数与其词法作用域的组合。内部函数引用了外部函数的变量，即使外部函数已返回，该变量仍被持有。常用于私有变量、柯里化、防抖节流；注意不当持有会导致内存泄漏。

### Q2. [进阶] 说说 Event Loop（事件循环）？
JS 单线程，同步任务进调用栈，异步回调进任务队列。微任务（Promise.then、queueMicrotask）优先于宏任务（setTimeout、IO）执行，每轮宏任务后清空所有微任务。理解它才能解释 `setTimeout(fn,0)` 与 Promise 的输出顺序。

### Q3. [基础] 防抖和节流的区别？
防抖（debounce）：事件触发后等待一段时间再执行，期间再触发则重新计时，适合搜索输入、窗口 resize；节流（throttle）：固定时间间隔内只执行一次，适合滚动、拖拽。二者都用定时器控制高频事件。

### Q4. [进阶] Vue 的响应式原理？
Vue2 用 Object.defineProperty 劫持属性读写，配合依赖收集（Dep/Watcher）在 setter 时通知更新；Vue3 改用 Proxy 代理整个对象，能监听新增/删除属性与数组索引变化，性能与覆盖度更好。

### Q5. [基础] 什么是跨域？怎么解决？
浏览器同源策略限制不同协议/域名/端口间的请求。解决：CORS（服务端加 Access-Control-Allow-Origin）、反向代理（同源转发）、JSONP（仅 GET，已少用）、或网关统一域名。

## Redis 与缓存

### Q1. [基础] Redis 有哪些常用数据类型？
String（计数/缓存）、Hash（对象属性）、List（队列/栈）、Set（去重/交集）、ZSet（排行榜，带分值）、以及 Bitmap、HyperLogLog、Geo 等。选型直接影响内存与操作复杂度。

### Q2. [进阶] 缓存穿透、击穿、雪崩分别是什么？
穿透：查不存在的数据，每次打到 DB；解决用布隆过滤器或缓存空值。击穿：热点 key 失效瞬间大量并发穿库；解决用互斥锁或逻辑过期。雪崩：大量 key 同时失效或 Redis 宕机；解决用错峰过期、多级缓存、高可用集群。

### Q3. [基础] RDB 和 AOF 持久化区别？
RDB 定时快照，恢复快、文件小，但可能丢最后一次快照后的数据；AOF 记录每条写命令，数据更全，但文件大、恢复慢。生产常混合持久化（Redis 4.0+）兼顾安全与效率。

### Q4. [进阶] 缓存与数据库如何保持一致？
常见「先更新 DB，再删缓存」（Cache-Aside + 延迟双删）降低不一致概率；读时旁路加载。强一致成本高，通常接受最终一致，用消息队列异步补偿。要避免「先删缓存再更新 DB」带来的并发脏读。

### Q5. [基础] 为什么 Redis 这么快？
纯内存操作；单线程避免锁竞争与上下文切换（6.0 后 IO 多线程但命令执行仍单线程）；IO 多路复用（epoll）处理海量连接；高效数据结构与协议。

## 分布式与微服务

### Q1. [基础] 微服务的优缺点？
优点：独立部署、技术异构、故障隔离、团队自治；缺点：分布式复杂度（网络、一致性、链路追踪）、运维成本高、事务跨服务难。是否拆分要看团队规模与业务边界，别过早微服务化。

### Q2. [进阶] 服务注册与发现是什么？
服务启动时把地址注册到注册中心（如 Nacos/Consul/Eureka），调用方从中心拉取可用实例列表并负载均衡。配合心跳探活实现自动上下线，是微服务动态扩缩容的基础。

### Q3. [进阶] 接口幂等性怎么保证？
同一请求重复提交产生同一结果。手段：唯一 ID + 去重表、乐观锁版本号、token 机制、状态机约束。支付/下单等写接口必须幂等，否则重试会造成资损。

### Q4. [进阶] 分布式锁怎么实现？
基于 Redis（SETNX + 过期时间，注意锁续期与误删，可用 Redisson 看门狗）或 ZooKeeper（临时顺序节点，公平可靠）。核心是「互斥 + 超时 + 防误删 + 高可用」，并考虑锁失效时的降级。

### Q5. [基础] 讲一下 CAP 理论？
分布式系统最多同时满足一致性（C）、可用性（A）、分区容错性（P）中的两个。网络分区不可避免，所以通常在 C 与 A 间取舍：CP（如 ZooKeeper，保一致） vs AP（如 Redis/Eureka，保可用最终一致）。
